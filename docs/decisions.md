# Decisions — OceanEmbed

- 2026-10-02 — Raw downloads behind a provider interface with a synthetic provider at native resolutions: no CMEMS/Earthdata credentials exist on this machine, so the whole pipeline must be buildable and testable without them.
- 2026-10-02 — Regridding with plain xarray/numpy (block-mean coarsen for finer grids, bilinear for same-resolution): all source grids are integer multiples of 0.25°, and xESMF/ESMF is painful to install on Windows.
- 2026-10-02 — Harmonised data stored as Zarr chunked one day per chunk: gives cheap random daily access for training without loading ~GBs into 16 GB RAM.
- 2026-10-02 — Model predicts the standardised anomaly from a harmonic climatology (train period only): removes the dominant seasonal/depth signal so the network spends capacity on the surface-driven variability, and gives a climatology baseline for free.
- 2026-10-02 — Embedding engine is a hybrid CNN-stem + Transformer encoder pretrained by masked surface reconstruction: matches the PRD's "attention-based hybrid / autoencoder" options and fits a 6 GB GPU (1500 tokens after 4× downsampling).
- 2026-10-02 — Validation uses individual Argo profiles via argopy (open access) as the primary in-situ source, with an optional loader for a user-supplied INCOIS gridded-ARGO file: INCOIS LAS has no stable programmatic API.
- 2026-10-02 — Temporal (date-range) train/val/test split instead of random: neighbouring days are highly autocorrelated, so a random split would leak.
- 2026-10-02 — Dashboard in Streamlit + Plotly: fastest route to an interactive PoC on top of a Python/xarray stack, no separate API server.
- 2026-10-02 — Virtual env kept at `C:\Users\mamid\.venvs\oceanembed`, outside the OneDrive project folder: avoids syncing several GB of packages.
- 2026-10-02 — zarr>=3 (stores are Zarr v3, read with consolidated=False): the current xarray passes `zarr_format` to zarr and no longer works with zarr 2.
- 2026-10-02 — erddapy<3 and pandas<3 pinned, and `SSL_CERT_FILE` pointed at certifi when unset: argopy 1.3 fails to import with erddapy 3, and aiohttp fails TLS verification with the Windows cert store on this machine (verified: real Argo fetch works with both fixes).
- 2026-10-02 — Synthetic raw files go to `data/raw_synthetic/` (config `paths.raw_dir`) instead of `data/raw/`: synthetic and real monthly files share names, so separate folders prevent accidentally harmonising fake data as real.
- 2026-10-02 — Separable matrix regridding (`Wy @ field @ Wx.T`, NaN-aware via a parallel valid-count pass) for both block-mean and bilinear: exact, fast, and one code path for the 50 % validity rule.
- 2026-10-02 — Regrid method chosen automatically from the native/target resolution ratio: the live DUACS dataset is now 0.125° (PRD says 0.25°), so SLA needs a 2×2 block mean, not bilinear.
- 2026-10-02 — Per-product dataset lists with validity windows (SSS: reprocessed until 2023-12, NRT from 2024-01): the single MY SSS dataset ends 2024-12-15, so the most recent fully covered test year (2025) needs the NRT dataset.
- 2026-10-02 — PoC period 2019–2025 (train 2019–23, val 2024, test 2025): every product covers it (tightest ends: OSCAR/DUACS 2026-01-16) and 2025 is the latest full calendar year.
- 2026-10-02 — Synthetic truth is analytic in (lat, lon, time) with smooth interior fields evaluated on a 0.25° grid and bilinearly interpolated to 1/12° and 0.05°: all products and Argo profiles come from one consistent world, ~10× faster than evaluating every native point.
- 2026-10-02 — Harmonic climatology reduces to mean-only (<180 d) or mean+annual (<548 d) for short train periods: seasonal harmonics are unidentifiable and would extrapolate wildly (matters only for the tiny test config).
- 2026-10-02 — Large data (synthetic/real raw + Zarr) kept outside OneDrive via `OCEANEMBED_DATA_ROOT=C:\Users\mamid\oceanembed_data`: several GB would otherwise sync.
- 2026-10-02 — PoC period moved to 2018-01-01..2024-12-15 (train 2018–22, val 2023, test 2024) using only the reprocessed SSS dataset: supersedes the 2019–2025 choice, which tested on NRT SSS after training on reprocessed SSS (a product shift that would contaminate the skill numbers).
- 2026-10-02 — Encoder adds an internal "visible" channel (all ones downstream) instead of changing the 12-channel dataset contract: the pretraining mask indicator stays inside the encoder, so pretraining and reconstruction share one input interface.
- 2026-10-02 — Pretraining decoder sees only the embedding map (no stem skips) and the encoder only ever sees the masked input: skips cannot leak hidden pixels, and the embedding itself must encode the surface state.
- 2026-10-02 — Whole splits preloaded into RAM (float32, ~2 GB train) rather than per-day Zarr reads or DataLoader workers: removes the loader bottleneck (14 ms/batch vs ~45 ms/item lazily) with no multiprocessing pitfalls on Windows.
- 2026-10-02 — fp16 autocast + GradScaler (not bf16) with SDPA attention and GroupNorm convs: memory-efficient attention keeps 1500 tokens x batch 8 at ~1.3 GB peak on the 6 GB GPU.
- 2026-10-02 — Val RMSE in degC computed as (anomaly error x per-depth anomaly std): the climatology cancels in prediction minus truth, so early stopping needs no date handling.
- 2026-10-02 — Baselines expose the same predictor interface as the model (x -> standardised anomaly), and ridge is one sklearn Ridge per depth fitted only on points valid at that depth: below-sea-floor points never bias a depth's fit, and evaluation can treat all methods uniformly.
- 2026-10-02 — `OCEANEMBED_OUTPUTS_ROOT` env override (mirrors the data-root one): checkpoints and embeddings are hundreds of MB and must stay out of OneDrive.
- 2026-10-02 — Synthetic pretrain/train budgets cut to 12 / 40 epochs (early stopping on val): with 2 training years the model memorises days and val metrics bottom out around epoch 5, so longer schedules only waste time; checkpoints are chosen on val (masked MSE for pretraining, degC RMSE for reconstruction).
- 2026-10-02 — Optional random-crop augmentation (`pretrain.crop` / `train.crop`, default off): crops made the pretraining curve smooth (val 0.181 vs 0.193) but worsened downstream val RMSE (1.71-1.82 vs 1.58-1.61 degC), so the synthetic config leaves it off; kept as a config option for the real-data run.
- 2026-10-02 — Metric accumulators store per-grid-point sums (n, x, y, x², y², xy, |e|, e²) and reduce afterwards: one streaming pass yields per-depth, per-basin, pooled and map statistics, and chunked evaluation is exactly equal to one-shot (sums are additive).
- 2026-10-02 — Correlation is always reported twice, `corr_raw` (temperatures) and `corr_anom` (climatology removed from prediction and reference): raw correlation is inflated by seasonal/spatial/vertical gradients, so only the anomaly version measures day-to-day skill.
- 2026-10-02 — `SurfaceOnlyDataset` (inputs only, batched contiguous reads) for predict / evaluate / Argo collocation: prediction must not need the target, so it works for dates without GLORYS and never touches `temp`.
- 2026-10-02 — Prediction NetCDF: float32 with `_FillValue` 9.96921e36 (netCDF default) for NaN, zlib level 4 + shuffle, one chunk per day, int32 `days since 1970-01-01` time; tagged ablations write to `predictions/<tag>/` so the default product directory only ever holds the final model.
- 2026-10-02 — Argo vertical rule: bracketing levels required, gap <= max(10 m, 0.2·z), no extrapolation, plus a surface exception (z <= 5 m may use the shallowest level within 10 m): Argo spacing is ~5-10 m near the surface and up to 100 m at depth, and interpolating across a hole larger than a fifth of the depth would make the "observation" a guess.
- 2026-10-02 — Argo collocation uses the grid cell containing the profile and the same UTC day, and scores only (profile, depth) rows where the observation, the mask, GLORYS and every method are finite: all methods then share exactly the same sample and the comparison is fair.
- 2026-10-02 — Argo metrics also include GLORYS itself and skill / anomaly correlation vs Argo, with an explicit note that GLORYS assimilates Argo (the comparison is independent of the model inputs, not of the training target).
- 2026-10-02 — Daily domain-mean RMSE series stored inside `metrics_glorys.json` (`daily_rmse`): it is only n_days x 15 floats per method, so no extra file format is needed for the dashboard.
- 2026-10-02 — `run-all` calls the CLI command functions in-process (resolved at call time): each step runs exactly the code of its own command, failures map to a non-zero exit code with a named step, and tests can monkeypatch a step.
- 2026-10-02 — `run_meta.json` (config snapshot, data source, splits, grid, absolute data paths) is rewritten by every output-producing command: the dashboard never guesses paths and old runs stay self-describing.
- 2026-10-02 — Monthly gridded-ARGO products are compared with the model's monthly mean and only for months entirely inside the evaluated period (daily products: same day): comparing a monthly mean with a single day would mix timescales.
- 2026-10-02 — Report figures use a sqrt depth axis (increasing downward, standard levels as ticks), the Okabe-Ito colour-blind-safe palette with one fixed colour per method, `viridis` for fields / RMSE and `RdBu_r` centred on zero for bias and differences: the thermocline needs resolution that a linear 0-1000 m axis hides.
- 2026-10-02 — `pythonpath = ["."]` in pytest config so tests import the dashboard data layer as `app.data_access` without packaging `app/` into the wheel.
- 2026-10-02 — Everything moved inside the project folder (`.venv/`, `data/`, `outputs/`, documents in `docs/`), superseding the earlier outside-OneDrive locations: the whole project must live in one self-contained folder; the env overrides stay only for tests.
- 2026-10-02 — Dashboard pages insert the repo root into `sys.path` and import `app.ui`: Streamlit only puts `app/` on the path and `app/` is deliberately not packaged into the wheel, so this is the smallest way to share one UI package across pages.
- 2026-10-02 — Custom `st.page_link` navigation with Streamlit's default page list hidden (`showSidebarNavigation = false`): the default nav shows file names such as `1_3D_Explorer`; custom links give readable names and keep the run selector and banner in one shared shell.
- 2026-10-02 — Map height fixed per layout slot instead of a locked aspect ratio: Streamlit cannot report the column width to the server, and locking the aspect left blank bands around maps; degrees are square only at about 1600 px window width, which is an accepted trade-off.
- 2026-10-02 — `streamlit>=1.64` and relative `run_meta.json` paths anchored at the project root (derived from the run directory): the dashboard uses `st.button(shortcut=...)`, and reading paths against the working directory would break when Streamlit is started elsewhere.
- 2026-10-02 — OSCAR / CCMP via per-granule OPeNDAP (`.dap.nc4` with a DAP4 constraint) as the default, global-granule download as automatic fallback: measured live, the subset is 0.2 / 0.75 MB per day (vs 32 MB) in about 2.2 s, byte-identical to the same region cut from the global granule, and works with the existing Earthdata login.
- 2026-10-02 — Harmony HOSS not implemented as a route: it failed for OSCAR ("variable /u does not have a grid_mapping") and took 15.8 s per CCMP day versus 2.2 s with OPeNDAP, for the same values.
- 2026-10-02 — OPeNDAP index ranges and variable/dimension layout come from the granule's DMR and coordinate arrays (fetched once per product, assumed constant across the collection) rather than hard-coded: OSCAR and CCMP order their dimensions differently and OSCAR's coordinate variables (`lon`) differ from its dimension names (`longitude`).
- 2026-10-02 — One atomic piece per day in `raw/_parts` and a month file merged only when complete: an interruption (or one failing day) never leaves a half-written or partial monthly file, and a re-run only fetches the missing days.
- 2026-10-02 — OPeNDAP is switched off for the rest of a run after 3 failures (refusals or exhausted retries): a refusing server (e.g. an unauthorised Earthdata application) would otherwise be asked once per remaining day, while the granule route is known to work.
- 2026-10-02 — Transfer ledger as one JSON line per completed download in `raw/_download_log.jsonl`, recording how bytes were measured (`wire` = compressed bytes on the connection, `file_size`, `unknown`): network volumes should be measured, not estimated, and CMEMS / argopy do not expose wire bytes.
- 2026-10-02 — `standardize` promotes 1-D coordinate variables on differently named dimensions and rebuilds datetime64 from cftime: the real OSCAR file has dimension `longitude` with variable `lon` (read as a 0..N index otherwise) and declares a julian calendar (cftime cannot be sliced with datetime64).
- 2026-10-02 — An Argo box with no profiles (ERDDAP HTTP 404, raised by argopy as FileNotFoundError) is an empty result, not an error: sparse boxes over land / empty ocean are normal for the 15 degree tiling.
- 2026-10-02 — Singleton depth axis of the CMEMS SSS is squeezed for surface fields in `process_variable`: the vertical interpolation needs at least two levels and is only meant for the 3-D temperature.
- 2026-10-02 — Final dashboard = React single-page app served by a FastAPI backend: Streamlit's rerun model and widget chrome cap the achievable quality, a custom front end needs a plain HTTP data API, and the Streamlit PoC stays untouched.
- 2026-10-02 — `data_access.py` moved into the package (`oceanembed.data_access`) with `app/data_access.py` as a re-export: the API is part of the installed package and must not import from the unpackaged `app/` folder.
- 2026-10-02 — FastAPI + uvicorn, read-only, GET only, localhost by default, CORS only for the Vite dev origins: the dashboard client needs OpenAPI docs and pydantic models, and nothing served is secret or writable.
- 2026-10-02 — NaN encoded as `null` by a custom response class that rounds arrays in float64 (3 decimals): Starlette's JSONResponse rejects NaN, a rounded float32 would print as 28.123000144958496, and rounding keeps a 15-level volume near 2 MB of JSON.
- 2026-10-02 — Large fields also offered as raw little-endian float32 (`format=f32` / `Accept: application/octet-stream`) with shape and colour range in `X-*` headers: NaN survives exactly, a volume is 1.44 MB, and the browser reads it straight into a `Float32Array`.
- 2026-10-02 — ETag from run_meta.json mtime + URL + Accept with `max-age=60, must-revalidate` and a 304 before any data read: every pipeline command rewrites run_meta.json, so a new run version invalidates caches without per-file bookkeeping.
- 2026-10-02 — Colour-range hints computed server-side (1st-99th percentile of prediction + target, symmetric 99th percentile of |x| for differences / anomalies): the UI never scans 360k values and prediction / target panels always share a scale.
- 2026-10-02 — Point time series read with `netCDF4` directly (under xarray's netCDF lock) and cached per cell: reading a column through xarray lazy indexing took ~4 s for 184 days, netCDF4 0.7 s.
- 2026-10-02 — Runs addressed by folder name (strict regex, direct child of the outputs root with a run_meta.json) and figure / product names accepted only if present in the directory listing: no user string ever becomes a path.
- 2026-10-02 — `depth` (metres, must equal a grid depth) and `depth_index` are separate parameters: `depth=5` would otherwise be ambiguous between 5 m and index 5 (50 m).
- 2026-10-02 — Ridge profile not offered for arbitrary points: it needs the fitted regressor and the day's standardised inputs per request; ridge is served where it is already computed (Argo matchups / profiles, metrics, error maps).
- 2026-10-02 — Ruff `per-file-ignores` E501 for `src/oceanembed/api/*` and bugbear `extend-immutable-calls` for FastAPI `Depends` / `Query`: long OpenAPI description strings and the standard FastAPI parameter idiom would otherwise need noise suppressions.
- 2026-10-02 — Final dashboard uses a light "printed atlas" direction (warm paper, serif headings, framed figure plates) instead of the dark PoC theme: the thermal colormap's cold end reads on paper but vanishes on dark, light survives projection, and figures can go straight into a report.
- 2026-10-02 — No chart, map or router library in `web/` (custom canvas map renderer with a shared camera, small SVG charts, ~100-line URL store): linked pan/zoom/hover across maps and one-frame depth/day scrubbing need direct control, and the dependency list stays at four runtime packages.
- 2026-10-02 — Difference, anomaly, profile and section are derived client-side from the float32 day volumes: one request per day then serves every depth and view without round trips.
- 2026-10-02 — Maps are plate carrée with unsmoothed 0.25° cells and a coastline from the model mask: shows exactly what the model produced (≤13 % E–W scale error at 30°N accepted).
- 2026-10-02 — TypeScript pinned to 5.9 and API types generated from a committed OpenAPI snapshot with a test: typescript-eslint/openapi-typescript do not support TS 6 yet, and the snapshot test catches API drift.
- 2026-10-02 — Long downloads run as detached processes (`Start-Process`) logging to `outputs/experiments/full_run_logs/`: background tasks of the development tooling are stopped after 10 minutes; downloads are resumable so a restart loses nothing.
- 2026-10-02 — Ridge and ablation day fields are precomputed NetCDF products (`predictions/ridge/`, `predictions/<tag>/`, ~150 MB each for a one-year test split) written by `run-all`, not computed per API request: the API then stays a pure reader (one 10 ms day read per method) and the served fields are exactly what `evaluate` scored.
- 2026-10-02 — `run-all` gets `ablation.no_pretrained` / `ablation.tag` config keys (on in every shipped config) instead of a CLI flag: the chain stays reproducible from the YAML alone and the pretraining decision comes from the same real run; the ablation trains before `evaluate` so the metrics and Argo matchups include it.
- 2026-10-02 — Temperature colour ranges of `/fields` always come from the main model and the target, whatever `method` is asked for: model / ridge / ablation panels then share a scale; diverging kinds keep each method's own 99th-percentile limit.
- 2026-10-02 — `/argo/profiles` keeps `n_profiles` (now: matches of the filters) and defaults to `limit=5000` with `has_more` instead of silently sub-sampling: a page is exactly the first rows of the sort order, so clients can always page through everything.
- 2026-10-02 — Daily anomaly correlation is the spatial (pattern) correlation over the grid points of one day and depth, stored next to the daily RMSE / bias; the existing `per_depth.corr_anom` stays the temporal per-point correlation.
- 2026-10-02 — `skill_vs_clim` maps use a diverging range symmetric about zero capped at 1 (skill is at most 1 but unbounded below): zero means "as good as climatology" and must sit at the neutral colour.
- 2026-10-02 — Product-file dates and the stats-file attributes are read with `netCDF4` directly: opening each monthly product with xarray cost ~0.4 s, so listing three methods took ~3 s on a cold server; it is ~50 ms now.
- 2026-10-02 — `/embeddings/similar` offers `center=true` (subtract the run's PCA-sample mean embedding): raw cosine similarity of the embeddings is dominated by a component common to all cells, centring spreads it over -1..1; the default stays the plain cosine the request asked for.
- 2026-10-03 — Period-wide colour ranges (`/ranges`) are estimated from 24 evenly spaced days with at most 6000 strided ocean values per day and depth and cached in memory per run version, not persisted: the API stays strictly read-only (it must also serve a run another process is still writing) and a cold computation costs 2-5 s.
- 2026-10-03 — `skill_vs_clim` map limit is the 95th percentile of |skill| over all methods at the depth, kept within 0.5..3 (replaces the fixed +-1 that saturated), and `range_info` reports data extremes and the count outside the range, so the UI can say when colours saturate rather than hide it.
- 2026-10-03 — `/embeddings/similar` returns `null` on land cells and excludes them from `similarity_range`: land embeddings carry no information and inflated the raw similarity range.
- 2026-10-03 — Pooled daily bias and pooled spatial anomaly correlation are derived in `evaluate` from the per-day, per-depth sums it already accumulates (no new accumulation); `synthetic` and `poc_trial` were backfilled by re-running `evaluate` (all older numbers reproduced exactly).
- 2026-10-03 — Unreadable (truncated) monthly product files are skipped when listing prediction methods and days: `predict` writes in place, so a month still being produced must not turn every endpoint into a 500.
- 2026-10-03 — Model-dependent field labels follow one pattern for every method (`<label> prediction`, `<label> minus GLORYS`), and product / field-method `kind` is `model` | `baseline` | `ablation`, so the UI can group methods without special-casing the main model.

- 2026-10-03 — Pretrained encoder kept as the documented design although the no-pretraining ablation scored ~3 % better on the real test year (1.04 vs 1.08 °C pooled 50–200 m, one seed): the gap is within the run-to-run variation seen earlier, the embedding engine is the PRD's core requirement, and the ablation stays visible in every table instead of being hidden.
- 2026-10-03 — GLORYS-vs-Argo is reported as the floor for the Argo validation: GLORYS itself is 1.08 °C from Argo over 50–200 m in 2024 with a +0.5–0.8 °C warm bias at 100–150 m (confirmed on the raw native-resolution files; +0.15 °C in 2018), so no model trained on it can be expected to beat that against the floats.
- 2026-10-03 — Argo fetch falls back to the scipy NetCDF-3 reader and retries per box: netCDF4's in-memory reader rejected a valid 2-row ERDDAP response deterministically, which argopy cannot recover from.
- 2026-10-03 — Overview and Explorer given different jobs (Overview = fixed result-at-a-glance panel at a thermocline depth, Explorer = free exploration): both had opened on the same map instrument, and a surface map flatters the model because the surface is an input.
- 2026-10-03 — README cut to a one-screen-per-section summary with the real results first; setup, CLI reference, requirement mapping and dataset table moved to `docs/usage.md`.
- 2026-10-03 — U-Net baseline = the same network with the 6 Transformer blocks replaced by 4 residual conv blocks of width 192 at H/4 (3.73 M vs 3.74 M parameters): changing only the bottleneck isolates attention at an equal parameter budget, whereas dropping the blocks would also remove ~2.6 M weights and confound capacity with architecture.
- 2026-10-03 — U-Net is trained from scratch only (no pretraining variant): the question it answers is "does attention add anything", and the like-for-like comparison is `scratch` vs `unet`.
- 2026-10-03 — MLP baseline sees exactly the ridge features and one shared 3 x 256 SiLU network trained on 1 M random train points with early stopping on a fixed validation sample: it differs from ridge only by non-linearity, so the gap to ridge measures what non-linearity alone buys; 3 seeds because it is cheap and its spread is small.
- 2026-10-03 — Research jobs reuse the preloaded train / validation arrays across the whole runner process: reloading ~7 GB per job would add minutes to each of ~19 jobs, and the arrays are read-only.
- 2026-10-03 — Each (method, seed) stores per-day, per-depth, per-basin sufficient statistics (`eval.npz`, ~2 MB) instead of predictions: every metric the report needs (including anomaly correlation and skill) and the bootstrap follow from sums, and 5 seeds x 3 methods of NetCDF would be ~2 GB.
- 2026-10-03 — Bootstrap replicates are day-count vectors applied by matrix product to the per-day sums: the same replicates then serve every method, depth, basin and metric, which makes the paired differences exact and the 2000-replicate bootstrap take seconds.
- 2026-10-03 — Block length is estimated from the data (median e-folding time of the daily pooled MSE; the main run's daily series give about 20-40 days, not 10-15) and reported with a sensitivity table: the daily errors persist for weeks and on the main run's errors the interval kept growing until blocks of about 30 days, so short blocks would understate it.
- 2026-10-03 — Intervals are over test days for the seed-mean model and seed spread is reported separately; a difference is called established only when the bootstrap interval excludes 0 and the seed ranges do not overlap: the day bootstrap cannot see training-seed variance.
- 2026-10-03 — `set_seed` also sets cuDNN to deterministic mode: CPU runs reproduce bit for bit (tested) and GPU runs closely; fully deterministic CUDA would need `use_deterministic_algorithms` and slower attention / upsampling backward passes for no change in conclusions.
- 2026-10-03 — Research commands load the config without rewriting `run_meta.json`, and the progress bars of training switch off when stderr is not a terminal: the main run's files must stay byte-identical, and a redirected multi-hour log would otherwise fill with bar updates.
- 2026-10-03 — R4 uses the reprocessed daily ARMOR3D dataset for the whole test year: it ends on 2024-12-31, so no reprocessed-to-near-real-time switch (the same trap as the SSS product) falls inside the test period.
- 2026-10-03 — ARMOR3D is regridded with `harmonize.process_variable` (the GLORYS path) and scored on the product's own daily steps: a different regridding or a temporal interpolation would change the comparison, not the product.
- 2026-10-03 — Argo scoring of ARMOR3D reuses the stored `validate-argo` matchups and drops rows where ARMOR3D is undefined for every product: one identical sample is the only fair comparison, and it avoids a second interpolation rule.
- 2026-10-03 — ARMOR3D's dependence on Argo is reported as a caveat plus a weak float-density check, not as a number: its inputs cannot be separated from the floats being scored, and no leave-out product is available.
- 2026-10-03 — The isotherm depth is the shallowest downward crossing from a valid warm surface, NaN otherwise: it is well defined for a profile with inversions, never extrapolates, and treats a column that ends while still warm as not bracketed.
- 2026-10-03 — Derived quantities are scored on cells where every product and GLORYS have a value: otherwise a product with more NaNs (shelf cells) would be scored on a different, easier sample.
- 2026-10-03 — Stratified skill stores per-day sums per stratum and reuses the block bootstrap; seasons restrict full-year replicates to their days, and "is the gain concentrated" is tested as a paired difference of gains between terciles rather than by comparing overlapping intervals.
- 2026-10-03 — R5 re-runs the R1 per-pixel MLP (seed 0) on the CPU instead of requiring stored fields: the stratified question is "advantage over point-wise models", the MLP has no prediction files, and inference on 350 days takes seconds.
- 2026-10-03 — R3 removes a variable by zeroing its input channels (all days, every lag) instead of shrinking the network: the layout and the initialisation stay those of the full-input model, so the R1 model of the same seed is an exact reference (a test shows the identity view trains bit-identically on the CPU), and zero is the training mean, the value missing data already take.
- 2026-10-03 — R3 uses the R1 `scratch` / `mlp` results of the same seeds as the full-input reference rather than retraining them: the code path is identical (tested), and it saves two thirds of an hour of GPU per Transformer seed.
- 2026-10-03 — Permutation importance permutes within the calendar month (a random derangement of each month's days, all channels of a group from the same donor day): a global shuffle would pair a July field with January inputs and credit the variable with the seasonal cycle the day-of-year channels already carry; the within-month version measures sub-monthly information and, by design, can rank variables differently from retraining (redundant inputs).
- 2026-10-03 — Permutation repeats are averaged at the level of the per-day sums and an unpermuted pass from the same code is stored with them: the interval then comes from the same day bootstrap as everything else, and the importance is a difference of two scores computed identically.
- 2026-10-03 — History models score every test day: the days before the test split are read from the store (inputs only, never a target), while the first k - 1 days of the training and validation splits are dropped; all history lengths are therefore compared on the identical test days.
- 2026-10-03 — The per-pixel MLP with history sees the ridge features plus the surface values of the previous days and is trained on the same sampled points as the full-input MLP: any change is then due to the inputs, not the sample.
- 2026-10-03 — Research scoring computes the per-region sums with one matrix product per field and reads the reference once for all passes: permutation importance needs about 16 passes per model, and the straightforward per-region loop of R1 would have made each pass take as long as a whole R1 evaluation (checked equal to `sums_from_arrays`).
- 2026-10-03 — Long training periods use an opt-in on-disk memmap cache (`train.cache: memmap`, float16) instead of changing `preload()`: existing configs stay bit-identical, 11 years (about 11 GB as float32) cannot be held in 16 GB of RAM, and float16 halves the disk reads at a measured round-off far below 0.01 degC (recorded in each cache's `meta.json`).
- 2026-10-03 — The cache is built in a `.tmp` folder, renamed after `meta.json` is written, and keyed by the statistics fingerprint, the split and the store identity: a partial build is never used and a stale or deleted cache is rebuilt, so deleting `data/processed/cache/` is always safe.
- 2026-10-03 — The point samples of ridge and the MLP are read from a memory map day by day (`gather`): 1 M random (day, pixel) pairs scattered over 10 GB would otherwise be one random file read each.
- 2026-10-03 — The long run is harmonised from the raw months in one pass instead of reusing the 2018-2024 months of `poc`: the month processing is deterministic and reuse would still need the sea-floor mask recomputed over the whole period; recomputing costs about 40 extra minutes of an unattended job and removes a way for the two stores to differ.
- 2026-10-03 — Every R2 job scores the whole two-year test split and the report slices it by year: one evaluation per model serves 2023, 2024 and pooled, each with its own block bootstrap, and a year difference uses independent resamples because the two years are different days.
- 2026-10-03 — The learning curve keeps the normalisation and climatology fitted on the full train period for every point: the question is how many training days the network needs, and refitting the climatology on two years would change the anomaly the network is asked to predict.
- 2026-10-03 — Long-period models are compared with the first run's models on 2024 by absolute RMSE (same days, same GLORYS, same replicates) and, separately, by skill against each run's own climatology: the two climatologies are fitted on different periods, so skill alone would mix the benefit of data with the benefit of a better baseline.
- 2026-10-03 — R2 fits its own ridge baseline on the long train split (saved in its job folder) because the main run's ridge is trained on 2018-2022; the Argo job never downloads (missing months are an error) and puts a profile-level bootstrap on the pooled 50-200 m RMSE and on the model-minus-method differences.
- 2026-10-04 — Input groups are a `model.input_groups` config field applied by zeroing the dropped channels inside the dataset (`x` and the point samples), not inside the network: one cache serves every input set, and training, prediction, evaluation, embedding export and the baselines all read the same inputs through one code path. A checkpoint records its groups and is refused with other ones.
- 2026-10-04 — `model.main_init: scratch|pretrained` decides how `recon.pt` is made; the other initialisation becomes an ablation (`ablation.pretrained` / `ablation.no_pretrained`, folder `predictions/<tag>/`). Defaults reproduce the old behaviour exactly, so existing configs and runs are unchanged.
- 2026-10-04 — The per-pixel MLP is opt-in per config (`baseline.mlp`) and stored as `checkpoints/mlp.pt` + `predictions/mlp/` next to ridge (reserved folder name, kind `baseline`); its training log goes to `logs/baselines/` so the dashboard's training curves (which list `logs/*.jsonl`) keep showing only the network.
- 2026-10-04 — A run can reuse another run's harmonised store, statistics and array cache (`paths.store`) instead of copying 4 GB; `harmonize`/`stats` refuse to touch a shared store, `run-all` replaces download/harmonize/stats by a `store` check, and the statistics' train period must equal the config's.
- 2026-10-04 — Per-year metrics are formed from per-year accumulators whose sum is the pooled period (sums are additive), written as an extra `per_year` block; every existing key keeps its meaning, so the dashboard is unaffected and single-year runs have no such block.
- 2026-10-04 — Input sets are chosen on the validation-year RMSE of the kept checkpoint, adopting a reduced set only if it beats the full set by more than the larger seed SD: the test years are scored after the decision, for every candidate, so the paper can state rule and outcome without the test data influencing the choice.
- 2026-10-04 — Live mode keeps one raw file per day and product under `data/raw_nrt/` (not monthly files): a revision replaces exactly its own day, an interrupted download resumes at the day, and pruning the window is deleting files; raw NRT and reprocessed files never share a folder.
- 2026-10-04 — A live day is available only when every input the model uses has data for it, and the window ends at the newest such day: reconstructing with one input missing would silently feed the model a zero channel.
- 2026-10-04 — NRT days are re-fetched and re-reconstructed for the newest `revision_days` on every update, and each day keeps its first-published inputs and reconstruction (`first_published/`): the size of a revision is then measured against what a user saw first, not against the previous update.
- 2026-10-04 — The live run is a normal run folder (`run_meta.json` with a `live` block, monthly NetCDF, surface store) flagged `live: true` in `/api/runs`, so the existing field endpoints serve it unchanged and a client can exclude it from its default-run choice without a second code path.
- 2026-10-04 — The live verification stores daily sums (n, error, squared error) per reference and depth band rather than scores, so any rolling window is one sum, a revised day is simply recomputed, and the record survives pruning of the window.
- 2026-10-04 — The input-shift check compares the NRT archive as it is now with the reprocessed products on the same days: it measures the product difference; first-publication error is bounded separately by the revision statistics.
- 2026-10-04 — The tree baselines use exactly the per-pixel MLP's 11 features and training sample (`sample_points`, same size order, seed = draw and model seed), with hyper-parameters picked on the validation year only from a small grid on a smaller sample: the comparison then differs from the MLP's only in the model family.
- 2026-10-04 — LightGBM is one regressor per depth with early stopping on the validation sample; the random forest is one multi-output forest (predicting 15 separate forests over 12 M test pixels would take hours) with depths below the sea floor filled with the climatological anomaly 0.
- 2026-10-04 — `start.bat` creates `.venv` itself, picks the CUDA PyTorch wheel only when `nvidia-smi` finds a GPU, never installs system software (a missing Python 3.12 or Node is reported and stops), and always starts on a free port: it is safe to run beside an already running server.
- 2026-10-04 — Released weights carry the statistics and the ocean mask in one `stats.nc`, so `predict --weights` needs only harmonised surface inputs (`harmonize --surface-only` skips the GLORYS target); results and weights are copied by `export-results` / `export-weights` so the folders can be recreated, with JSON written compactly to stay small.
