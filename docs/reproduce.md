# Reproducing the results, and cleaning up

This is written for the owner of the project folder. Short version: the **results** (`results/`) and the **trained model**
(`models/final/`) are small and are kept in git; everything else on disk (`data\`, `outputs\`, `.venv`) is generated and can
be deleted and rebuilt. Nothing below deletes anything by itself - the commands in section 2 are for you to run.

All sizes were measured on this machine on 2026-10-04 (GB = 1024 MB). Times marked *measured* were timed on this machine
(RTX 3050 6 GB); the others are estimates from the runbook (`docs/runbook.md`) and are labelled as such.

## 2. Three clean-up levels (commands are for you to run; run from the project root in PowerShell)

Close any running `oceanembed serve` first. Check the path in each line before you press Enter; `Remove-Item -Recurse -Force`
cannot be undone (OneDrive's recycle bin aside).

**Level 1 - keep everything the dashboard needs** (all processed stores and all outputs stay; the raw downloads, the
synthetic raw files, the training-array cache and the archived experiments go). Frees about **41.8 GB**.

```powershell
Remove-Item -Recurse -Force data\raw
Remove-Item -Recurse -Force data\raw_synthetic
Remove-Item -Recurse -Force data\processed\cache
Remove-Item -Recurse -Force outputs\experiments
Remove-Item -Recurse -Force web\node_modules
```

Cost: re-running `download`, `validate-argo` for new months or `research r4` needs the downloads again (section 3); training
rebuilds the cache itself.

**Level 2 - keep only weights and results** (`models\`, `results\`, code, configs, docs; also keeps `.venv` so you can still run
`predict --weights`). Frees about **53.2 GB**.

```powershell
Remove-Item -Recurse -Force data
Remove-Item -Recurse -Force outputs
Remove-Item -Recurse -Force web\node_modules, web\dist
```

Cost: no dashboard until you rebuild `final` (section 3, option B); predictions for any day are still one command away
(option A).

**Level 3 - delete all generated data** (everything that git does not hold, including the Python environment). Frees about
**58.0 GB**.

```powershell
Remove-Item -Recurse -Force data, outputs, .venv
Remove-Item -Recurse -Force web\node_modules, web\dist
```

What remains is the repository: code, configs, docs, `results\` and `models\final\`.

## 3. Coming back from a fresh clone

**Environment (about 20 min, about 5 GB).**

```powershell
git clone <the repository> ; cd OceanEmbed
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu126
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

**Logins** (only for downloads; see `docs/runbook.md` section 1-2): Copernicus Marine (`copernicusmarine.exe login`) and NASA
Earthdata (`.netrc`). Argo needs none.

**Option A - fast path: only the released weights.** Predicts the temperature of any days from the five surface products,
without GLORYS and without training. Edit `time` in `configs\predict_surface.yaml` to the days you want, then:

```powershell
.\.venv\Scripts\oceanembed.exe download  --config configs\predict_surface.yaml -v sst -v sla -v sss -v currents -v winds
.\.venv\Scripts\oceanembed.exe harmonize --config configs\predict_surface.yaml --surface-only
.\.venv\Scripts\oceanembed.exe predict   --config configs\predict_surface.yaml --weights models\final --start 2024-06-01 --end 2024-06-30
```

Download: about 35 MB per month (estimated from the sizes above), a few minutes; harmonise and predict: about a minute per
month (a month of prediction took 7 s on the GPU, measured). The model uses SST and sea level only, but the harmonise step expects all five
files, so download all five. Output: `outputs\predict_surface\predictions_from_weights\`.

**Option B - rebuild the main run and the dashboard** (download about 30 GB, about 8-13 h unattended, then 76 min of
compute, measured):

```powershell
.\.venv\Scripts\oceanembed.exe download  --config configs\poc_long.yaml          # about 30 GB; resumable; add -v to run products in parallel terminals
.\.venv\Scripts\oceanembed.exe harmonize --config configs\poc_long.yaml          # about 80 min
.\.venv\Scripts\oceanembed.exe stats     --config configs\poc_long.yaml
.\.venv\Scripts\oceanembed.exe run-all   --config configs\final.yaml --skip-existing   # 76 min: training, MLP, ablation, predictions, metrics, Argo, report
.\.venv\Scripts\oceanembed.exe export-results --config configs\final.yaml        # optional: rewrites results\
cd web; npm install; npm run build; cd ..; .\.venv\Scripts\oceanembed.exe serve --port 8765
```

The download step fetches Argo for every month of the period; for the final run only 2023 - 2024 are needed
(`download -v argo` is optional, `validate-argo` fetches the missing test months itself, about 30 min).
Retraining gives numbers within the seed spread (about 0.003 degC) of the published ones, not identical ones: GPU training is
not bit-reproducible.

**Option C - re-run the research.** `research r1 ... r5`, `research r2`, `research final-inputs` (commands in `docs/usage.md`);
R2 needs the same data as option B plus about 4 h, the input-set selection about 2 h more. Their numbers are in
`results\research\` already.

## 4. What is, and is not, in the GitHub repository

| In the repository | Not in the repository |
|---|---|
| code (`src\`, `app\`, `web\src`), tests, configs | `data\` (raw downloads, harmonised stores, caches) |
| documentation (`docs\`, `README.md`) | `outputs\` (checkpoints of every run and seed, predictions, embeddings, metrics folders, logs) |
| `results\`: metrics JSON, report and figures of the final run, the summaries of every research stage | prediction NetCDF files (they are regenerated by `predict`) |
| `models\final\`: weights, statistics and ocean mask, baselines, model card (18 MB; no file over 50 MB) | `.venv`, `web\node_modules`, `web\dist` |
| | credentials (they live in your Windows user folder, never in the project) |
